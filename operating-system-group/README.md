# OS Scheduler Simulator

**운영체제 CPU 스케줄링 알고리즘 시뮬레이터**

## 구현된 알고리즘

| # | 알고리즘 | 유형 | 특징 |
|---|---------|------|------|
| 1 | **FCFS** | 비선점 | 도착 순서대로 처리 |
| 2 | **SJF (SRTF)** | 선점 | 남은 CPU 시간 최단 우선 |
| 3 | **Round Robin** | 선점 | Time Slice=4, 순환 실행 |
| 4 | **Priority (Static)** | 선점 | 정적 우선순위 |
| 5 | **Priority + Aging** | 선점 | 동적 우선순위, 기아 방지 |
| 6 | **Multi-Level Queue** | 선점 | 3단계 큐 + Feedback |
| 7 | **Rate Monotonic** | 실시간 | 주기 기반 |
| 8 | **EDF** | 실시간 | 마감시한 기반 |

## 실험 결과 분석

### 테스트 데이터 (professor_data.txt)
**7개 프로세스**: P1~P7  
**총 CPU 시간**: 83  
**총 I/O 시간**: 30  
**특징**: CPU-bound 중심 (I/O 비율 26.5%)

| PID | 도착 | 우선순위 | CPU | I/O | 설명 |
|-----|------|---------|-----|-----|------|
| P1  | 0    | 3       | 15  | No  | CPU-bound |
| P2  | 2    | 2       | 12  | Yes | I/O-bound |
| P3  | 5    | 1       | 8   | No  | 높은 우선순위 |
| P4  | 1    | 5       | 25  | No  | 낮은 우선순위, 긴 작업 |
| P5  | 0    | 0       | 4   | No  | 실시간 (주기=10) |
| P6  | 0    | 0       | 7   | No  | 실시간 (주기=25) |
| P7  | 8    | 4       | 12  | Yes | I/O-bound |

### 성능 비교표

```
Algorithm                         Avg WT    Avg TAT   CPU Util%  Context SW
---------------------------------------------------------------------------
FCFS                               34.71      46.57       94.32           9
SJF (Preemptive/SRTF)              24.71      36.57      100.00           9
Round Robin (q=4)                  40.86      52.71      100.00          22
Priority (Static)                  25.00      36.86      100.00          12
Priority with Aging                28.43      40.29      100.00          54
Multi-Level Queue                  34.57      46.43      100.00          13
Rate Monotonic (RM)                 2.00       7.50      100.00           1
Earliest Deadline First (EDF)       2.00       7.50      100.00           1
```

### 핵심 분석

#### 1. 평균 대기 시간 (Avg WT)
- **최고**: SJF (24.71) - 이론적 최적
- **최저**: RR (40.86) - 공정하지만 비효율적
- **실시간**: RM, EDF (2.00) - 실시간 프로세스만 고려

#### 2. CPU 사용률
- **FCFS**: 94.32% - I/O 대기로 약간의 유휴
- **나머지**: 100% - 유휴 시간 없음

#### 3. 문맥 전환
- **최소**: RM/EDF (1회) - 실시간 프로세스 2개만 처리 (P5→P6)
- **일반**: FCFS/SJF (9회)
- **최대**: Priority + Aging (54회) - 빈번한 우선순위 변경

#### 4. 알고리즘별 특징

**FCFS**
- 간단하지만 Convoy Effect 발생
- P4(25) 때문에 다른 프로세스들이 대기

**SJF**
- 평균 대기 시간 최소
- P4가 58까지 대기 (Starvation)

**Round Robin**
- 공정하고 응답 시간 빠름
- 문맥 전환 많음 (오버헤드)

**Priority + Aging**
- 기아 현상 방지
- 문맥 전환 가장 많음 (54회)

### 알고리즘 선택 가이드

| 목적 | 권장 알고리즘 |
|-----|-------------|
| 평균 응답 시간 최소화 | SJF |
| 공정성 중요 | Round Robin |
| 기아 방지 | Priority + Aging |
| 대화형 시스템 | Multi-Level Queue |
| 실시간 시스템 | RM 또는 EDF |

### CPU 활용률 100%에 대한 설명

**질문**: CPU 활용률이 100%로 나오는데, 이것이 현실적인가?

**답변**: 이 시뮬레이션에서 100%가 나오는 것은 **정상이며**, 다음 이유 때문입니다:

#### 1. 시뮬레이션 환경의 특성
- **이상적인 환경**: 시스템 오버헤드, 인터럽트 처리 시간 등을 무시
- **완벽한 스케줄링**: 즉시 문맥 전환 가능 (실제로는 수 마이크로초 소요)
- **연속적인 워크로드**: 프로세스들이 겹쳐서 도착하여 항상 실행 가능한 프로세스 존재

#### 2. 테스트 데이터의 특성
교수님 데이터는 **CPU-bound 중심**:
- 총 CPU 시간: 83
- 총 I/O 시간: 30
- I/O 비율: 26.5% (상대적으로 낮음)

**결과**:
- FCFS: 94.32% (I/O 대기로 약간의 유휴)
- 선점형 알고리즘: 100% (I/O 중에도 다른 프로세스 실행)

#### 3. 현실 시스템과의 비교

| 요소 | 시뮬레이션 | 현실 시스템 |
|-----|-----------|-----------|
| 시스템 오버헤드 | 0% | 5-10% |
| 문맥 전환 비용 | 무시 | 수 마이크로초 |
| I/O 비율 | 26.5% | 50-80% (일반적) |
| 프로세스 도착 | 연속적 | 불규칙적 |
| **실제 CPU 활용률** | **90-100%** | **60-80%** |

#### 4. 실제 측정 예시

만약 I/O-bound 워크로드를 사용하면:
```
# I/O가 많은 데이터 (예상)
CPU 활용률: 60-70%
```

#### 결론
✅ **100% CPU 활용률은 이 시뮬레이션에서 정상**
- CPU-bound 워크로드
- 이상적인 스케줄링 환경
- 선점형 알고리즘의 효율성

❌ **현실 시스템에서는 60-80%가 일반적**
- I/O 대기 시간
- 시스템 오버헤드
- 불규칙한 워크로드

## 입력 형식

### 파일 형식
```csv
# PID,도착시간,우선순위,"실행패턴",주기,마감시한

1,0,3,"15",0,0              # CPU-bound
2,2,2,"3,10,4,12,5",0,0     # I/O-bound
5,0,0,"4",10,10             # 실시간
```

### 실행 패턴 설명
- 짝수 인덱스 (0,2,4...): **CPU 버스트**
- 홀수 인덱스 (1,3,5...): **I/O 버스트**

예: `"3,10,4,12,5"` = CPU(3) → I/O(10) → CPU(4) → I/O(12) → CPU(5)
